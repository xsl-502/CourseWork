# 算法设计与分析

本文给出作业 3 和 4 的中文题意整理与详细解答。约定图均为无向图，顶点覆盖的大小指覆盖集合中顶点的数量。

## 1. 基本概念

### 1.1 多项式归约

设 `A` 和 `B` 是两个判定问题。称 `A` 可以在多项式时间内归约到 `B`，记作

\[
A \le_p B,
\]

如果存在一个多项式时间可计算的函数 `f`，使得对任意输入 `x` 都有

\[
x \in A \iff f(x) \in B.
\]

因此，如果能够在多项式时间内解决 `B`，就可以先计算 `f(x)`，再调用 `B` 的算法，从而在多项式时间内解决 `A`。

归约的方向很重要：`A \le_p B` 表示 `B` 至少和 `A` 一样难。若 `A` 已知为 NP-困难，且 `A \le_p B`，则 `B` 也是 NP-困难。

### 1.2 P、NP 与 EXP 的关系

- `P`：可以由确定性图灵机在多项式时间内解决的判定问题。
- `NP`：给定一个候选解，可以在多项式时间内验证其正确性的判定问题；等价地，可以由非确定性图灵机在多项式时间内解决。
- `EXP`：可以由确定性图灵机在指数时间内解决的问题，例如时间上界为 `2^{n^c}`（某个常数 `c`）。

已知的包含关系是

\[
P \subseteq NP \subseteq EXP.
\]

其中：

1. `P ⊆ NP`，因为多项式时间内已经能求出答案的问题，当然也能在多项式时间内验证答案。
2. `NP ⊆ EXP`，因为可以枚举所有长度为多项式的候选证书，并逐一进行多项式时间验证。
3. `P ≠ EXP` 已由时间层次定理证明，因此至少有一个包含关系是严格的。
4. `P = NP` 是否成立仍是公开问题。若 `P = NP`，所有 NP 问题都有多项式时间算法；若 `P ≠ NP`，则存在可验证但不能在多项式时间内求解的问题。

本题通常要求掌握上述包含链和 `P` 与 `NP` 的未解决关系，而不是假定 `P = NP` 或 `P ≠ NP`。

### 1.3 证明 NP-完全性的主要步骤

要证明判定问题 `B` 是 NP-完全的，通常分为两步：

1. **证明 `B ∈ NP`**：给出一个多项式长度的证书，并说明验证证书是否代表“是”实例可以在多项式时间完成。
2. **证明 `B` 是 NP-困难的**：选择一个已经知道是 NP-完全的问题 `A`，构造多项式时间归约 `A ≤p B`，并证明归约保持“是”和“否”的对应关系。

完成这两步后，根据定义可得 `B` 是 NP-完全问题。

## 2. 最大团问题是 NP-完全的

### 2.1 判定版本

最大团的优化版本要求找出最大完全子图。证明 NP-完全性时使用其判定版本：

> **CLIQUE**：给定无向图 `G=(V,E)` 和整数 `k`，是否存在至少包含 `k` 个顶点的团？

### 2.2 `CLIQUE ∈ NP`

证书是一个顶点集合 `S ⊆ V`，且 `|S| ≥ k`。验证算法检查 `S` 中任意两个不同顶点是否都有边相连。最多检查 `O(|S|^2)` 对顶点，因此验证时间是多项式时间。

### 2.3 从最大独立集归约

最大独立集的判定版本是：给定图 `G=(V,E)` 和整数 `k`，是否存在至少 `k` 个互不相邻的顶点？该问题是 NP-完全的。

给定最大独立集实例 `(G,k)`，构造 `G` 的补图

\[
\overline G=(V,\overline E),
\]

其中对任意不同顶点 `u,v`，有

\[
\{u,v\}\in \overline E
\iff
\{u,v\}\notin E.
\]

归约输出 `(\overline G,k)` 作为 CLIQUE 实例。构造补图只需检查每一对顶点是否在原图中有边，因此时间为 `O(|V|^2)`，是多项式时间。

### 2.4 正确性证明

对任意顶点集合 `S ⊆ V`：

\[
S \text{ 是 }G\text{ 中的独立集}
\iff
\text{任意 }u,v\in S\text{ 在 }G\text{ 中不相邻}
\]

\[
\iff
\text{任意 }u,v\in S\text{ 在 }\overline G\text{ 中相邻}
\iff
S \text{ 是 }\overline G\text{ 中的团}.
\]

因此

\[
G\text{ 有大小至少为 }k\text{ 的独立集}
\iff
\overline G\text{ 有大小至少为 }k\text{ 的团}.
\]

所以 `INDEPENDENT-SET ≤p CLIQUE`。由于最大独立集是 NP-完全问题，CLIQUE 是 NP-困难的；再结合 `CLIQUE ∈ NP`，得到：

\[
\boxed{\text{CLIQUE 是 NP-完全问题。}}
\]

最大团的优化版本至少与其判定版本一样难，因此最大团优化问题是 NP-困难的。

## 3. 由判定算法构造大小为 `k` 的顶点覆盖

设有一个多项式时间判定算法 `D(H,t)`，它返回图 `H` 是否存在大小至多为 `t` 的顶点覆盖。若题目将“大小为 `k`”理解为恰好 `k`，只需注意：一个大小至多为 `k` 的覆盖可以通过补入任意顶点扩展为恰好 `k`（当 `k≤|V|`），所以两种表述对构造过程等价。

### 3.1 构造算法

1. 先调用 `D(G,k)`。若返回“否”，则不存在大小为 `k` 的顶点覆盖；若返回“是”，继续构造。
2. 令 `C=∅`，当前图为 `H=G`，剩余预算为 `t=k`。
3. 当 `H` 仍有一条边 `(u,v)` 时，调用 `D(H-u,t-1)`。
   - 若返回“是”，把 `u` 加入 `C`，令 `H←H-u`，`t←t-1`。
   - 若返回“否”，把 `v` 加入 `C`，令 `H←H-v`，`t←t-1`。
4. 当 `H` 没有边时停止，输出 `C`。若要求恰好 `k` 个顶点，再从未选顶点中任取 `k-|C|` 个加入 `C`。

这里 `H-u` 表示删除顶点 `u` 及其关联的所有边。

### 3.2 正确性证明

设当前边为 `(u,v)`。

- 若 `D(H-u,t-1)` 返回“是”，则 `H-u` 有一个大小至多为 `t-1` 的顶点覆盖。把 `u` 加入后，原图 `H` 中所有与 `u` 相连的边由 `u` 覆盖，其余边由 `H-u` 中的覆盖集合覆盖。因此 `H` 有一个包含 `u` 且大小至多为 `t` 的顶点覆盖。
- 若 `D(H-u,t-1)` 返回“否”，则不存在大小至多为 `t` 且包含 `u` 的顶点覆盖。由于边 `(u,v)` 必须被覆盖，任何可行覆盖都必须包含 `v`。因此选择 `v` 不会排除所有可行解。

每一步都保持不变式：当前已选集合 `C` 可以扩展为原问题的一个大小至多为 `k` 的顶点覆盖。每次选择一个端点并从图中删除它，最终图没有边；于是所有原图边都已被 `C` 覆盖，且 `|C|≤k`。补入顶点后仍是顶点覆盖，得到大小恰好为 `k` 的解。

### 3.3 运行时间

每次迭代至少删除一个顶点，因此最多进行 `|V|` 次。每次只调用一次判定算法，并进行一次图删除操作。若判定算法运行时间为 `T(n,m)`，总时间为

\[
O(|V|\cdot T(|V|,|E|)+\operatorname{poly}(|V|,|E|)),
\]

仍然是多项式时间。这说明顶点覆盖问题具有自归约性：多项式时间判定器可以转化为多项式时间构造器。

## 4. 最长路径问题是 NP-困难的

### 4.1 目标问题的判定版本

使用如下判定问题：

> **LONGEST-PATH**：给定图 `H` 和整数 `L`，是否存在一条包含至少 `L` 个顶点的简单路径？

若能在多项式时间内求出最长路径，就能比较最长路径长度与 `L`，从而解决该判定问题。因此证明判定版本 NP-困难即可推出优化版本 NP-困难。

### 4.2 从哈密顿回路构造实例

给定 HAMILTONIAN-CYCLE 实例 `G=(V,E)`，设 `|V|=n`。任选一个顶点 `v∈V`，构造图 `H`：

1. 删除 `v`，保留 `G-v`。
2. 添加两个新顶点 `v'` 和 `v''`。
3. 对 `v` 在 `G` 中的每个邻居 `u`，同时加入边 `(v',u)` 和 `(v'',u)`。
4. 再添加两个叶顶点 `s,t`，只加入边 `(s,v')` 和 `(v'',t)`。

此时 `H` 有 `n+3` 个顶点。输出 LONGEST-PATH 实例 `(H,n+3)`。构造过程只需遍历原图边，时间为多项式时间。

### 4.3 正确性证明

**若 `G` 有哈密顿回路。**

设哈密顿回路经过顺序为

\[
v,u_1,u_2,\ldots,u_{n-1},v.
\]

由于 `u_1` 和 `u_{n-1}` 都是 `v` 的邻居，图 `H` 中存在路径

\[
s,v',u_1,u_2,\ldots,u_{n-1},v'',t,
\]

它经过 `H` 的全部 `n+3` 个顶点。因此 `H` 有哈密顿路径。

**若 `H` 有经过全部 `n+3` 个顶点的路径。**

`s` 和 `t` 是叶顶点，所以它们必须是该路径的两个端点。除去 `s` 和 `t` 后，路径必然形如

\[
v',u_1,u_2,\ldots,u_{n-1},v''
\]

或反向顺序，其中 `u_1,\ldots,u_{n-1}` 恰好是 `G-v` 的全部顶点。将两端的 `v'` 和 `v''` 合并为原顶点 `v`，由于它们只连接到 `v` 原来的邻居，就得到

\[
v,u_1,u_2,\ldots,u_{n-1},v,
\]

这是一条经过 `G` 每个顶点恰好一次的哈密顿回路。

因此

\[
G\text{ 有哈密顿回路}
\iff
H\text{ 有包含 }n+3\text{ 个顶点的路径}.
\]

所以 `HAMILTONIAN-CYCLE ≤p LONGEST-PATH`。由于哈密顿回路是 NP-完全问题，LONGEST-PATH 是 NP-困难的，进而“寻找最长路径”的优化问题也是 NP-困难的。

## 5. Load Balancing 的近似算法

### 5.1 问题模型

给定 `n` 个作业和 `m` 台相同机器。作业 `j` 的处理时间为 `p_j>0`，每个作业必须完整地分配给一台机器。机器负载是分配到该机器上的作业处理时间之和，目标是最小化最大机器负载：

\[
C_{\max}=\max_{i=1}^m L_i.
\]

记最优值为 `OPT`。

### 5.2 List Scheduling 算法

按任意顺序处理作业。每次把下一个作业分配到当前总负载最小的机器。

```text
输入：作业处理时间 p1,...,pn；机器数 m
初始化 m 台机器负载为 0
对每个作业 j=1,...,n：
    选择当前负载最小的机器 i
    将作业 j 分配给机器 i
    L_i ← L_i + p_j
输出该分配方案
```

实现时可以用最小堆维护机器负载：取出最小负载机器，增加 `p_j` 后重新插入。

### 5.3 近似率证明

设算法产生的最大负载为 `C`，取使该最大负载产生的最后一个作业为 `j`，其处理时间为 `p_j`，它开始处理时所在机器的负载为 `S`。于是

\[
C=S+p_j.
\]

在作业 `j` 分配前，所有已分配作业的总处理时间为 `P-p_j`，其中 `P=\sum_{r=1}^n p_r`。因为算法把 `j` 放到最小负载机器上，

\[
S\le \frac{P-p_j}{m}.
\]

所以

\[
C\le \frac{P-p_j}{m}+p_j
=\frac{P}{m}+\left(1-\frac1m\right)p_j.
\]

另一方面，任何调度方案都满足两个下界：

\[
OPT\ge \frac{P}{m}
\]

因为总工作量为 `P`；并且

\[
OPT\ge p_j
\]

因为作业 `j` 必须完整地放在某台机器上。因此

\[
C\le OPT+\left(1-\frac1m\right)OPT
=\left(2-\frac1m\right)OPT.
\]

故 List Scheduling 是一个

\[
\boxed{2-\frac1m}
\]

近似算法，即其输出最大负载不超过最优值的 `2-1/m` 倍。

### 5.4 运行时间

- 直接扫描所有机器寻找最小负载：每个作业耗时 `O(m)`，总时间为 `O(nm)`。
- 使用最小堆：初始化堆耗时 `O(m)`；每个作业执行一次删除最小值和一次插入，耗时 `O(log m)`，总时间为

\[
O(m+n\log m).
\]

空间复杂度为 `O(m)`，不计输入作业本身的存储空间。

因此，List Scheduling 在多项式时间内运行，并具有 `2-1/m` 的近似保证。
